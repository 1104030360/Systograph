## 遇到的問題與解決

1. **T7 Critical（reviewer 抓到）**：`exc_info` 把未遮蔽 secret + 絕對路徑寫進
   log 流（pytest 會把它渲染進失敗報告 → CI/PR 通道）。→ 遮蔽集中到
   `safe_log_event` 內（render → `mask_text` → `redact_local_paths` → 當 message；
   `record.exc_info` 恆 None），政策一句話寫進 docstring。
2. **T6 修一壞一（re-reviewer 抓到）**：round 1 把 pointer 容錯放進共用 helper，
   讓 `/api/map/report` 在最新 project pointer 壞掉時**靜默改端別的 project 的
   report**。→ round 2 拆成兩個 policy：report 端 fail-closed（任何 pointer 不可讀
   → None → 404，絕不替換——「誰是最新」不可知時不猜）；hydrate 保留 best-effort。
3. **計畫過時**（多處，全部以證據改判）：T4/T5 的 route 觸發情境已被 13.5 刪掉
   （換 mapping-proposals）；T10 的 `0.8s→<0.1s` import 宣稱實測推翻（真收益 =
   副作用歸零）；Plan 1 的 17 cast / 4 檔 sed 基線已被 Plan 2 改變（15 cast /
   helper choke point）；C1 亦發現稽核「無測試覆蓋」判定錯誤。
4. **T3 掛死守門**：disconnect 迴圈的守門測試在回歸時會掛死整個 pre-commit
   （`wait_for` 對不 yield 的迴圈無效）→ 改為呼叫計數器第 6 次直接
   `AssertionError`，回歸時 0.07s 判死。
5. **trace_all.sh 11 個失敗**：實測為 pre-existing fixture/資料問題（變更前後
   worktree 對照完全一致、0×404）→ 列入 phase8 任務 3（scripts 更新）處理。
