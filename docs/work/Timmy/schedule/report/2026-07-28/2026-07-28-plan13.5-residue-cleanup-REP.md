## 測試方式

- 每個行為變更 task：先寫失敗測試（RED 輸出留存於 task report）→ 最小實作 → GREEN；
  整合測試用 BDD Given/When/Then docstring（如 `test_normal_v2_build_populates_recommended_next_checks`）。
- 純搬移 task：先讓測試 import 新路徑（RED: ModuleNotFoundError）→ 搬移 → GREEN，
  搬移內容以機械比對（byte-compare）驗證 verbatim。
- 零行為 task（D/E）：套件數不變 + schema sha256 不變 + 逐句 truthfulness 查核。
- 每個 commit 過 pre-commit 完整 gate（ruff→format→mypy→全套 pytest），無一次 `--no-verify`。
- 每 task 由獨立 reviewer 做 spec compliance + code quality 雙驗收；
  發現 Important 即進 fix loop（共 5 輪，全部一輪內收斂）；最後 whole-branch final review。

## 遇到的問題與解決

1. **A1 循環 import**：計畫原定把 `RecommendedNextCheck` 搬進 `models/scan.py`，但
   `scan.py` 已 runtime import `system_map.Evidence`，反向 import 成環（兩種順序都
   `ImportError`，sandbox 實測）。→ 改判：獨立模組 `core/models/recommended_next_check.py`
   （只 import pydantic，結構性不可能成環），計畫檔同步記錄裁定。
2. **C1 的 brief 前提錯誤**：稽核宣稱「無測試覆蓋 legacy fallback」，實際兩個測試走過
   該路徑且是 `GET /api/detail-scans/{id}` 全 repo 唯一覆蓋。→ 遷移測試到 active path
   而非刪除，覆蓋率不降，residue 報告的誤判記入計畫。
3. **C6 gate 一次性化**：搬走原檔後第二次 `--apply` 會誤回 `cutover_blocked=False`
   （exit code 被機器消費）。→ 裁定 quarantine 袋（`*.original.json`）併入 gate；
   執行時再發現字面規格（`*.legacy.json`）會讓乾淨轉換永久誤擋——implementer 以證據
   改判 glob，reviewer 驗證三個論證全部成立。
4. **C6 證據覆寫風險**：`os.replace` 無條件覆寫會讓「從 backup 還原→重跑」情境毀掉
   唯一 byte-exact 原始證據。→ 比照 sibling 加 exists-guard（目的地既有 byte-exact 版勝出）。
5. **Final review 抓到契約謊言**：MODEL-CONTRACT §5.3 宣稱 checks 一定指向具體
   component/endpoint，但 evidence-typed risk hints（如 `secret_config`）實際 fallback 到
   `target_type="system"`，而 A3 測試的過濾正好遮住它。→ 文件補 `system` fallback 與
   slugged id 格式；測試放寬到全部四種 target_type 逐型別 containment + 至少一條
   非 system check 的精度守門。
6. **其他**：B1 註解理由被 B2 自己推翻（重寫為 lifetime-independence）；B3 需要連動
   `map_build_pipeline.py`（brief 未列，purity 需要）；census digest 是手算記錄
   （recipe 已精確寫入 REP，並標注無 executable assertion）。
