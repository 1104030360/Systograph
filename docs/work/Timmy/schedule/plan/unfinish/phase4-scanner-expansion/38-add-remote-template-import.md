# Remote Template Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 支援受控匯入外部 reference template，並保留 provenance、digest、schema validation 與信任邊界。

**Architecture:** Remote template 是 data-only artifact。Import service 可驗證、保存 metadata 與提供 local registry，但不得執行任何 template code、hook、script，不得下載 dependencies，不得改 scanner read-only/filesystem policy。

**Tech Stack:** Pydantic v2, HTTP client with egress policy only if remote URL enabled, digest verification, pytest.

## Scope

- First implementation supports local file import into managed template registry.
- Remote URL/Git import remains disabled by default and must use explicit opt-in.
- Every imported template must pass schema validation and digest/provenance recording.
- Imported template cannot contain executable fields.

## Out of scope

- 不做 template marketplace。
- 不支援 postinstall、script、hook、callback。
- 不下載模型或 dependencies。
- 不把 remote template 當 trusted scanner facts。

## Acceptance Criteria

- Local template import is schema-validated, digest-pinned, provenance-recorded, and data-only.
- Default app cannot fetch remote URLs or Git refs.
- No template code/hook/script can execute.
- Scanner canonical facts remain generated by deterministic providers, not imported template claims.
