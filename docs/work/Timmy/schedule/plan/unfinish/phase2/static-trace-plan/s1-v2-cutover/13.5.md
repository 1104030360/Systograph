## Stage A：RA-4 — recommended_next_checks 功能回補（裁定：功能缺失，必須補）

### 現況與缺口（audit 實證）

系統目前有**兩套**互不相干的 next-check 機制：

| | 來源 | 觸發 | 覆蓋面 | v2 現況 |
|---|---|---|---|---|
| **System 1（scan-fact 驅動）** | `RecommendedNextCheckService.derive()`（`system_map_normalize_service.py:91-264`）+ `core/rules/recommended_next_check_rules.toml` | endpoints、missing runtime/RAG-trust slots、privacy risk hints（published port / secret-like config / egress / 本地持久化） | runtime_readiness / privacy_exposure / rag_knowledge_trust，target 精確到 component_instance / slot / endpoint | **死路**：`AiSystemMapV2` 無此欄位（`ai_system_map_v2.py:425-449`），viewer 只在 `legacy_source is not None` 時填（`viewer_session_service.py:111-124`）→ 正常 v2 build 的 `graph.recommended_next_checks` 恆為 `[]`（實測） |
| **System 2（profile 驅動）** | `profile_registry.toml` 每 node 的 `recommended_next_checks` 字串 | profile status ∈ {partial, undetermined, conflicted}（`profile_finding_assembler.py:177-181`） | capability review 建議（純文字，無 target 結構） | **活著**：進 `readiness_report.json`（`readiness_report_service.py:63-80`）與 per-node `GraphNodeModel.recommended_next_checks`（`viewer.py:107`），markdown renderer 當 fallback（`graph_markdown_renderer.py:235-246`） |

缺的是 System 1：**privacy exposure 與 runtime readiness 的 scan-fact 檢查在 v2
完全消失**，System 2 蓋不到（profile registry 不看 risk hints / endpoints）。
Plan 18 的保留清單也明列 `recommended_next_check_rules.toml`（`18-*.md:37`），
證明產品意圖是保留此能力——回補是對齊既有決策，不是新功能。

### 設計決策（本計畫定案）

1. **落點：canonical map 本體**（`AiSystemMapV2.recommended_next_checks`），不是只放
   GraphViewModel。理由：reload path（`BuildManifestService.load`）只有 map artifact
   可讀，沒有 raw scan facts——不進 map 的話 reload 後 checks 就消失。v1 也是放 map
   本體（`RagSystemMap.recommended_next_checks`，`system_map.py:325`），對稱。
2. **derive 掛點：`SystemMapV2MaterializationService.materialize`**。該方法內
   `raw_scan` / `detection` / `endpoints` / `risk_hints` 四個輸入齊備
   （`system_map_v2_materialization_service.py:68-110`），與 v1 的
   `SystemMapNormalizeService.assemble` 掛點完全對稱。derive 邏輯**一行不改**
   （slot 觸發表吃的是 scan-phase 的 `ComponentDetectionResult.components_by_slot`，
   v2 pipeline 照樣產生）。
3. **Service 搬家成版本中立 module**。`RecommendedNextCheckService` 目前住在 v1 檔
   `system_map_normalize_service.py`——回補後它是 active v2 path 的一環，不能繼續住在
   Plan 15 要隔離的 rollback-only 檔案裡。
4. **Schema 變更是 additive**：optional 欄位、default `[]`，不進 `required`。但
   v2 schema 是 `additionalProperties: false`，pin 舊 schema 的嚴格 validator 會拒絕
   新 artifact——依 AGENTS.md 標準必須在 MODEL-CONTRACT 記 migration note（Task A5）。
5. **adapter 同步補 mapping**：`SystemMapV1ToV2Adapter` 目前**丟棄** v1 的
   `recommended_next_checks`（grep 零命中）——這正是 viewer 需要 `legacy_source`
   特例的原因。補上 mapping 後 viewer 的 legacy 特例可以收斂。
