# 1. 可以直接套用 legacy v1 linear baseline 架構嗎？

可以，尤其是 MVP。

legacy v1 linear baseline base 大概是：

```text
Data Sources
  ↓
Document Loader
  ↓
Chunking
  ↓
Embedding Model
  ↓
Vector Store

User Query
  ↓
Retriever
  ↓
Retrieved Chunks
  ↓
Prompt Builder
  ↓
LLM
  ↓
Answer / Citation
```

這跟你 repo 目前的 `rag-core-v1.json` 非常接近。你現在的 slots 包含：

```text
data_sources
document_loader
chunking
embedding_model
vector_store
app_api_or_orchestrator
query_processing
retriever
prompt_builder
llm
citation_or_response_composer
guardrails
observability
```

而且 flow 也分成 indexing 與 query_answer。

所以如果你問：

> 我可不可以先用 legacy v1 linear baseline 當 base？

答案是：

```text
可以，而且這是目前最務實的 MVP 起點。
```

# 2. 但不要把它說成「所有 RAG 都是 legacy v1 linear baseline」

這是重要差異。

## 可以這樣說

```text
Systograph uses a baseline RAG template inspired by the common Naive / 2-Step RAG pipeline.
```

中文：

```text
Systograph 使用一個受 Naive / 2-Step RAG 啟發的 baseline RAG template，作為最小共同骨架。
```

## 不建議這樣說

```text
All RAG systems are based on legacy v1 linear baseline.
```

中文：

```text
所有 RAG 都是 legacy v1 linear baseline 的延伸。
```

這句太武斷。
像 GraphRAG、Self-RAG、Multimodal RAG、MRAG，它們確實還有 retrieval + generation 的共同精神，但 topology 不一定像 legacy v1 linear baseline 那麼線性。

---

# 3. 正確理解：legacy v1 linear baseline 可以當「base graph」，但不是「universal schema」

你可以這樣分：

| 層                        | 可不可以用 legacy v1 linear baseline | 說明                                                      |
| ------------------------ | --------------: | ------------------------------------------------------- |
| MVP visual base graph    |              可以 | 最好理解、最好畫、最好 demo                                        |
| baseline readiness check |              可以 | 檢查 loader、chunking、embedding、retriever、LLM、citation 很合理 |
| canonical contract 名稱    |      不建議叫 naive | 應叫 `rag-core-v1` 或 `legacy-v1-linear-baseline-core`                  |
| 所有 RAG 變體的完整 topology    |             不可以 | GraphRAG / Self-RAG / Agentic RAG 會超出線性架構               |
| profile fragment 組合基底    |              可以 | 其他 profile 可以插入、旁路、覆蓋某些節點                               |

---

# 4. 你應該怎麼設計

我建議你用這個模式：

```text
rag-core-v1
= legacy v1 linear baseline-inspired baseline
= Common RAG readiness base
≠ 所有 RAG 的完整架構
```

然後其他 profile 不要取代整個 base，而是「插入」或「覆蓋」部分 graph。

---

## 例子一：Hybrid RAG

Base legacy v1 linear baseline 原本是：

```text
Query → Retriever → Vector Store → Prompt Builder
```

Hybrid RAG 改成：

```text
Query
  ↓
Dense Retriever ─┐
                  ├→ Fusion → Prompt Builder
Sparse Retriever ┘
```

所以它不是整個 template 換掉，而是替換 retrieval fragment。

---

## 例子二：Reranker / Advanced RAG

Base 原本是：

```text
Retriever → Prompt Builder
```

Reranker 插入：

```text
Retriever → Reranker → Prompt Builder
```

LlamaIndex 的 Advanced Retrieval Strategies 也包含 reranking、recursive retrieval、query transformations、composable retrievers 等，這些都比較像加在 baseline 上的 retrieval enhancement，而不是完全不同的 schema。([維基百科][1])

---

## 例子三：Corrective RAG

Base 原本是：

```text
Retriever → Prompt Builder
```

Corrective RAG 插入：

```text
Retriever
  ↓
Retrieval Evaluator
  ├─ good enough → Prompt Builder
  └─ insufficient → Query Rewrite / Web Search / Second Retrieval
```

所以 CRAG 不是要一個完全獨立 template，而是加上 corrective fragment。

---

## 例子四：GraphRAG

Base 原本是：

```text
Chunking → Embedding → Vector Store
```

GraphRAG 可能變成：

```text
Documents
  ↓
Entity / Relationship Extraction
  ↓
Knowledge Graph
  ↓
Community Summary
  ↓
Graph Retrieval
  ↓
Context Assembly
  ↓
LLM
```

這種就不是單純插一個小 node，而是 knowledge representation 這段大幅不同。
但你仍然可以在 UI 上保留 base 概念，只是把 `Knowledge Store` 區塊顯示為 graph-based profile。

# 5. 最推薦的命名

我不建議你在程式裡叫：

```text
legacy-v1-linear-baseline-v1
```

因為以後你會遇到命名問題：

```text
GraphRAG 是不是 legacy-v1-linear-baseline-v1 的子類？
Self-RAG 是不是 legacy-v1-linear-baseline-v1 的子類？
Multimodal RAG 是不是 legacy-v1-linear-baseline-v1 的子類？
```

這會怪。

比較推薦：

```text
rag-core-v1
```

或：

```text
legacy-v1-linear-baseline-v1
```

或：

```text
rag-readiness-core-v1
```

然後文件寫清楚：

```text
rag-core-v1 is a baseline RAG readiness profile inspired by the common Naive / 2-Step RAG pipeline.
```

這樣最穩。

# 7. 最終判斷

你的想法可以這樣 refine：

```text
Base RAG 直接用 legacy v1 linear baseline 架構，可以。
但它在 Systograph 裡應該被命名成 baseline RAG / rag-core-v1。
legacy v1 linear baseline 只是一個實作參考與視覺起點，不是所有 RAG 的完整 universal template。
```

一句話：

> **MVP 用 legacy v1 linear baseline 當 base 是對的；產品架構上要叫 baseline，而不是把全世界 RAG 都硬說成 naive。**
