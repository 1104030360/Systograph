## Execution Strategy (Linus Style)

### Principle 1: Fix What's Broken First
"理論上很完美但實際上當掉的程式碼就是垃圾"
- 優先修復 51 個失敗測試
- 不要加新測試直到現有測試全部通過

### Principle 2: Test What Matters
"不要為了覆蓋率而測試 trivial code"
- 專注在 Agents (核心邏輯)
- 專注在 Integration (實際使用流程)
- Utils 的 getter/setter 不需要 100% 覆蓋率

### Principle 3: Simplicity Over Perfection
"如果測試需要超過 3 層 Mock，重新思考設計"
- 保持測試簡單明瞭
- 避免過度 Mock
- 測試實際使用情境，不是理論情境

### Principle 4: Never Break Userspace
"測試的目的是確保不破壞現有功能"
- 所有新測試必須反映實際使用方式
- 不為了測試而改變生產程式碼
- Regression tests 優先於 feature tests
