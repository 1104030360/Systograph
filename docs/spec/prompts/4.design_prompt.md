## 4. 強制 Contract Decisions

除非前三階段產生更新且有明確證據，design 必須保持：

- 產品是 scanner / release-readiness gate，不是 builder、chatbot或完整 observability平台；
- input 是 AI system repo / workflow artifacts，不預設一定是 RAG或Agent；
- Two-Phase Analysis：deterministic facts first，bounded semantic analysis second；
- active target 是 generic `ai-system-map/v2`，v1 採 expand-and-contract migration；
- canonical truth只有 `ai_system_map.json`；derived/projection/runtime不得 write back；
- `rag_evidence_gate` + conditional `basic_rag_pipeline_check`；
- fixed ten-plane / 52-node reference map + repo overlay；
- assessment五態：`detected / partial / undetermined / not_detected / conflicted`；
- activation六態與 assessment分離；
- evidence kind：direct / indirect / explicit-negative；
- `not_detected` 必須通過 coverage gate；
- Mapping Completeness不是 confidence/readiness/quality score；
- Python擁有 executable semantics，TOML只擁有 metadata；
- `project_id / scan_id / snapshot_id / build_id / environment_id` identity分離；
- Apply重用 snapshot、建立 immutable child build、不重掃repo、不patch舊JSON；
- active artifacts使用 `generated_from_build_id`；`run_id`只限 legacy migration說明；
- Phase2 persistence是 repository protocols + atomic local JSON；database adapter延後；
- static execution是Phase2 P0，但 `runtime_verified=false`；
- Plan 12只凍結邊界；dynamic runtime implementation是post-Phase2。

## 7. Design Quality Rules

- 具體定義資料流、owner、輸入、輸出、invariants與failure behavior。
- 不使用「適當處理」「之後補上」「視情況」等不可驗證描述。
- 不新增規格未提及的產品能力。
- 不建立第二套canonical truth、v2 model、profile writer、projection或Apply pipeline。
- 清楚標示 assumption、limitation與open question；不要把假設寫成confirmed fact。
- 對高風險contract change提供migration、rollback與compatibility gate。
- 不公開private chain-of-thought；只記錄證據、精簡rationale與決策。

## 8. 禁止事項

- 不修改production code、tests、schemas、frontend或Phase2 plan files。
- 不建立implementation plan。
- 不執行target repo或安裝其dependencies。
- 不把raw source整包交給LLM。
- 不聲稱尚未存在的model/service/schema/test已完成。
- 不使用DeepResearch/prototype內容直接定義production contract。
- 不因外部工具不可用就捏造查證結果。

## 9. Self-review Gate

寫完後自行檢查並直接修正：

1. Placeholder：不得有未解釋的 TBD/TODO。
2. Internal consistency：identity、status、activation、artifact與dependency前後一致。
3. Current/target separation：planned內容沒有被寫成current implementation。
4. Scope：dynamic runtime與database沒有被塞回Phase2 critical path。
5. Traceability：所有既有Phase2 plans的design responsibility都有被涵蓋。
6. Testability：每個critical invariant都有可驗證的acceptance方向。
7. Security：沒有raw secret、absolute path或unsafe scanner behavior。

- 寫入的檔案；

- 主要contract裁決；
