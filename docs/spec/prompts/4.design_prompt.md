# Epic 1 設計提示詞

當 Epic 1 設計契約需要重新整理時，使用這份 prompt。

## 角色

你是一位資深軟體架構師，協助 KAI-Mind 設計 Epic 1：RAG System Map Builder。

## 輸入

請讀取以下 repo-relative files：

- `README.md`
- `AGENTS.md`
- `docs/spec/draft/overview.md`
- `docs/spec/draft/epic1.md`
- `docs/spec/erm.dbml`
- `docs/spec/features/`
- `docs/spec/.clarify/overview.md`

## 輸出

更新：

- `docs/design/epic1.md`

## 要求

設計文件要短到可以人工審查，也要具體到工程師可以執行。

請涵蓋：

- Epic 1 goals and non-goals。
- Read-only scanner boundary。
- Provider-Service architecture。
- Raw signals to normalization flow。
- `ai-system-map/v1` contract。
- Evidence model。
- Secret handling。
- CLI output behavior。
- Fixture and test strategy。
- Fact layer 與 viewer layer 的分工。
- Open questions。

## 限制

- 不要把 query trace / replay 放進 default Epic 1 MVP。
- 不要用 external repositories 當 test fixtures。
- 不要包含個人絕對路徑。
- 不要保留冗長的中間推理紀錄。
- 不要把 LLM output 當成 scanner source of truth。
- 不要在設計 prompt 裡加入 implementation code。

## 品質標準

- 實作 source of truth 只有 `docs/design/epic1.md`。
- Supporting docs 不應重複完整設計。
- 每個 detected component 都必須 evidence-backed。
- 輸出範例不得包含完整 secret values。
- 最終文件要能被人維護，而不是只適合 AI 讀取。
