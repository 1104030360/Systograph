# Epic 1 Design Prompt

Use this prompt when the Epic 1 design contract needs to be refreshed.

## Role

You are a senior software architect helping KAI-Mind design Epic 1: RAG System Map Builder.

## Inputs

Read these repo-relative files:

- `README.md`
- `AGENTS.md`
- `docs/spec/draft/overview.md`
- `docs/spec/draft/epic1.md`
- `docs/spec/erm.dbml`
- `docs/spec/features/`
- `docs/spec/.clarify/overview.md`

## Output

Update:

- `docs/design/epic1.md`

## Requirements

The design must be concise enough for human review and specific enough for engineering execution.

Cover:

- Epic 1 goals and non-goals.
- Read-only scanner boundary.
- Provider-Service architecture.
- Raw signals to normalization flow.
- `ai-system-map/v1` contract.
- Evidence model.
- Secret handling.
- CLI output behavior.
- Fixture and test strategy.
- Work split between fact layer and viewer layer.
- Open questions.

## Constraints

- Do not make query trace / replay part of the default Epic 1 MVP.
- Do not use external repositories as test fixtures.
- Do not include personal absolute paths.
- Do not preserve long intermediate reasoning logs.
- Do not treat LLM output as scanner source of truth.
- Do not add implementation code in the design prompt.

## Quality Bar

- One source of truth for implementation: `docs/design/epic1.md`.
- Supporting docs should not repeat the full design.
- Every detected component must be evidence-backed.
- Full secret values must not appear in output examples.
- The final document should be maintainable by humans, not just generated by AI.
